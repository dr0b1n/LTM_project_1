COMPLETED PROJECT CONTEXT FOR REPORT WRITING AND FUTURE AI PROMPTS

Document purpose
This file records the final implemented state of the RAG-Powered Vendor Compliance Auditor. It is intended to support the final report, presentation, demonstration, repository maintenance, and future AI conversations. It supersedes earlier planning assumptions where the completed implementation differs from the original proposal.

IMPORTANT SCOPE STATEMENT
This project is a small, local, synthetic, non-production demonstration. It proves that document extraction, privacy processing, local embeddings, vector retrieval, structured local-model analysis, validation, evaluation, and reporting can be connected into a working RAG workflow. It is not production software, legal advice, or an autonomous compliance decision system.

Final decisions must remain with a qualified human reviewer. Generated findings may be inaccurate, especially when the smaller local instruction model produces malformed or weak responses. The project therefore preserves retrieved evidence, validates citations, flags uncertain outcomes, and supports human review.

2. COMPLETED PROJECT SUMMARY
======================================================================

The completed application reviews synthetic vendor contracts against a version-controlled set of enterprise security, privacy, and operational policy requirements.

The application performs the following end-to-end workflow:

1. Accepts a text-based synthetic PDF through Streamlit.
2. Validates and extracts page-level text from the PDF.
3. Detects selected PII using Microsoft Presidio and spaCy.
4. Replaces selected PII with typed placeholders.
5. Splits sanitized text into page-aware chunks.
6. Generates local 384-dimensional embeddings using granite-embedding:30m through Ollama.
7. Stores sanitized chunks and metadata in a persistent ChromaDB collection.
8. Embeds each selected policy requirement.
9. Retrieves the top three relevant sanitized contract chunks.
10. Sends the policy and retrieved evidence to a local Ollama instruction model.
11. Validates the model response using Pydantic.
12. Verifies that non-MISSING findings cite a real retrieved chunk.
13. Replaces model-supplied provenance with authoritative application metadata.
14. Displays the policy, evidence, finding, explanation, and remediation in Streamlit.
15. Runs the full 12-policy baseline as a complete audit.
16. Compares results with synthetic expected findings when a matching file exists.
17. Exports complete results as JSON and a summary as CSV.

The completed system goes beyond the original minimum proposal. The original plan suggested three to five policies and one or two contracts. The final project contains a 12-policy baseline, multiple synthetic agreements, complete-audit execution, simple ground-truth evaluation, exports, and a polished Streamlit interface.

======================================================================
3. PROBLEM STATEMENT
======================================================================

Vendor contracts may contain commitments relating to encryption, access control, privileged access, security logging, vulnerability remediation, incident notification, audit rights, data retention, data deletion, subprocessors, and service continuity.

Manual review is repetitive and can miss:
- absent commitments;
- weaker thresholds;
- vague language;
- conflicting clauses;
- exceptions;
- commitments placed in unexpected sections; and
- evidence that does not actually support the policy requirement.

The project addresses this problem by retrieving relevant contract passages for an explicit policy and generating a structured, evidence-backed review finding. The generated explanation does not replace the contract evidence. Retrieval rank alone is not treated as proof of compliance.

16. SMALLER-MODEL RELIABILITY HANDLING
======================================================================

Observed issue
The smaller 3B model was much faster than the 8B model but produced more malformed or internally inconsistent findings, especially non-MISSING findings without valid chunk citations.

Integrity rule retained
The project did not weaken the basic evidence-integrity rule. A normal non-MISSING finding must cite a retrieved chunk.

Complete-audit fallback
The batch audit runner converts recoverable model-generation or validation failures into conservative fallback findings rather than losing the entire policy result.

Fallback behavior with retrieved evidence
- Status: REVIEW_REQUIRED
- Confidence: 0.0
- Highest-ranked retrieved clause displayed for inspection
- Human review required
- Explanation states that the model response could not be validated
- Retrieval rank is not presented as proof of compliance

Fallback behavior without evidence
- Status: MISSING
- Confidence: 0.0
- No cited clause
- Human review required

Purpose
This tradeoff improves demonstration completion speed while making uncertainty visible. It improves workflow reliability, not model accuracy.

27. RESULTS FOR THE FINAL REPORT
======================================================================

Report-safe result statement
The project successfully demonstrated an end-to-end, local-first RAG workflow for synthetic vendor-contract review. The application extracted page-level contract text, redacted selected PII, generated local embeddings, stored sanitized chunks in ChromaDB, retrieved policy-relevant evidence, generated structured findings with a local Ollama model, validated cited chunks, ran a complete 12-policy audit, evaluated supported synthetic contracts, and exported audit results.

Observable completed results
- Multiple synthetic vendor contracts can be processed.
- Relevant sanitized clauses can be retrieved for an explicit policy requirement.
- Findings preserve evidence text, page number, chunk ID, and retrieval distance.
- Model-generated provenance is not trusted over application metadata.
- Invented chunk citations are rejected.
- The complete audit continues when individual model responses fail.
- Smaller-model failures can be surfaced as REVIEW_REQUIRED rather than silently treated as compliant.
- Expected-findings files enable simple status and page comparison.
- Results can be downloaded as JSON and CSV.

Claims to avoid
- Do not claim production readiness.
- Do not claim legal validity.

28. DESIGN DECISIONS AND RATIONALE
======================================================================

Decision: Local-first processing
Rationale: Reduces exposure of sensitive contract text and demonstrates private local AI processing.

Decision: Synthetic contracts only
Rationale: Avoids confidential organizational data and enables known expected outcomes.

Decision: Redact before embedding
Rationale: Limits selected PII exposure in embeddings, ChromaDB, retrieval, and LLM prompts.

Decision: Explicit policy JSON
Rationale: Keeps thresholds and requirements outside model memory and makes rules reviewable.

Decision: Same embedding model for documents and queries
Rationale: Maintains vector-space compatibility.

Decision: Top-three retrieval
Rationale: Simple, transparent, and adequate for demonstration.

Decision: Pydantic structured output
Rationale: Converts free-form generation into a constrained application contract.

Decision: Application-authoritative provenance
Rationale: Prevents the model from inventing evidence text, page numbers, policy metadata, or retrieval distance.

Decision: Chunk citation validation
Rationale: Ensures non-MISSING findings refer to the retrieved evidence set.

Decision: Conservative batch fallback
Rationale: Allows a faster 3B model to complete the demonstration while clearly flagging uncertain output.

Decision: Direct Streamlit-to-service calls
Rationale: Minimizes architecture and keeps the prototype explainable within the limited project scope.

Decision: ChromaDB runtime data excluded from Git
Rationale: The index is generated, machine-specific, and reproducible from active synthetic source files.

32. SHORT PROJECT ABSTRACT
======================================================================

The RAG-Powered Vendor Compliance Auditor is a local-first demonstration system that reviews synthetic vendor agreements against version-controlled security, privacy, and operational policy requirements. The application extracts page-level PDF text, redacts selected personally identifiable information using Microsoft Presidio and spaCy, splits sanitized content into page-aware chunks, generates local embeddings with granite-embedding:30m, and stores the vectors in ChromaDB. For each policy, the system retrieves the top three relevant evidence chunks and uses a local Ollama instruction model to produce a structured finding. Pydantic validation and chunk-citation checks prevent unsupported evidence references, while application-controlled metadata preserves the authentic clause, page, chunk ID, and retrieval distance. The completed Streamlit application supports single-policy review, a complete 12-policy audit, conservative fallback handling for smaller-model failures, synthetic status and page evaluation, and JSON and CSV export. The project demonstrates successful integration of privacy processing, retrieval, local inference, validation, and human-centered review using only synthetic data. It is a non-production decision-support prototype and does not provide legal advice.

======================================================================
33. SHORT CONCLUSION
======================================================================

The completed project shows that a local RAG pipeline can support transparent vendor-contract review without relying on unsupported model claims. The system connects PDF extraction, selected PII redaction, local embeddings, ChromaDB retrieval, structured Ollama analysis, Pydantic validation, complete-audit execution, synthetic evaluation, and reporting in one understandable workflow. The strongest design feature is evidence integrity: findings are tied to retrieved contract chunks, while authoritative page and provenance data come from the application rather than the model. Although the prototype is not production-ready and the smaller model requires conservative fallback handling, the project meets its primary goal of demonstrating a working, privacy-aware, evidence-backed compliance-review workflow.
